### Задание 1. От исходного кода к байткоду

#### Часть 1. Режимы запуска

**Фрагмент байткода** (получен командой python -m dis task_1.py):

- LOAD_SMALL_INT и LOAD_CONST загружают константы

**Ответ на контрольный вопрос:** Байткод CPython нельзя считать машинным кодом процессора, потому что байткод - это набор инструкций для виртуальной машины CPython (программного интерпретатора), а не для реального процессора. Реальный процессор не умеет его исполнять напрямую. Машинный код процессора зависит от конкретной архитектуры (x86, ARM и т. д.) и выполняется аппаратно без дополнительного посредника. Байткод Python является промежуточным представлением, одинаковым для всех платформ, а его выполнение организует виртуальная машина CPython.

### Задание 2. Имена, объекты и сравнение

**Исходный код** task_2.py**:**

print("Типы:", type(a), type(b), type(c))

**Прогноз (записан до запуска):**

Python

\# a == b -> True (одинаковые значения)

\# a is b -> True (b = a, оба имени указывают на один объект)

\# a == c -> True (одинаковые значения)

\# a is c -> False (c создан через int(), это новый объект)

**Фактический результат:**

text

Типы: &lt;class 'int'&gt; &lt;class 'int'&gt; &lt;class 'int'&gt;

Идентификаторы: 1951798243792 1951798243792 1951801121904

a == b: True

a is b: True

a == c: True

a is c: False

Прогноз совпал с результатом. b = a не создаёт новый объект - оба имени ссылаются на один и тот же объект 1000. int("1000") создаёт новый объект с тем же значением, но другим идентификатором.

**Схема связей имён и объектов:**

a ──┐

&nbsp;   ├──► int(1000)   \[id: 1951798243792\]

b ──┘

c ─────► int(1000)   \[id: 1951801121904\]

**Разница между** \== **и** is**:**

- \== проверяет равенство значений двух объектов.
- is проверяет идентичность объекто**в**: являются ли два имени ссылками на один и тот же объект в памяти (сравнивает id()).

**Изменение значения** c **на** None **и проверка:**

Python

c = None

print("c после присваивания None:", c)

print("Корректная проверка c is None:", c is None)# True - корректная проверка на None

**Исследование интернирования строк:**

Python

first = "python"

second = "py" + "thon"

print("first == second:", first == second) # True

print("first is second:", first is second) # True

Результат first is second равен True в CPython из-за механизма интернирования строк: интерпретатор может хранить одну копию строки "python" и привязывать к ней оба имени.

**Правило применения** \== **и** is**:**

- is используется только для сравнения с синглтонами: None, True, False.
- \== используется для сравнения значений чисел, строк и всех остальных объектов.

**Ответы на контрольные вопросы:**

1.  Инструкция b = a не создаёт копию объекта. Она создаёт новое имя b и связывает его с тем же объектом, на который ссылается a. В памяти существует один объект, два имени.
2.  type() возвращает тип объекта. id() возвращает уникальный целочисленный идентификатор объекта - адрес в памяти в реализации CPython.
3.  None является синглтоном: в программе всегда существует ровно один объект None. Поэтому проверка is None абсолютно надёжна и семантически точна. Числа и строки не являются синглтонами, поэтому для них нужно сравнивать значения через ==.

### Задание 3. Числовые типы, операции и преобразования

#### Эксперимент A. int и арифметические операторы

Пример результатов:

- x + y = 22, тип int
- x - y = 12, тип int
- x \* y = 85, тип int
- x / y = 3.4, тип float
- x // y = 3, тип int
- x % y = 2, тип int
- x \*\* y = 1419857, тип int

**Объяснение различия** / **и** //**:** Оператор ‘/’ выполняет истинное деление и всегда возвращает float, даже если деление нацело. Оператор ‘//’ выполняет целочисленное деление и возвращает int при делении двух int, отбрасывая дробную часть.

#### Эксперимент B. Большие целые числа

Python

print("2 \*\* 1000 =", 2 \*\* 1000)

Результат - 302-значное число:

text

10715086071862673209484250490600018105614048117055336074...

**Объяснение:** В Python тип int имеет произвольную точность: он не ограничен разрядностью регистра процессора. Размер числа ограничен только доступной оперативной памятью. В большинстве других языков (C, Java, C++) целые числа имеют фиксированную разрядность, и при переполнении происходит ошибка или молчаливое переполнение.

#### Эксперимент C.float

Python

import math

result = 0.1 + 0.2

print("result =", result) # 0.30000000000000004

print("result == 0.3:", result == 0.3) # False

print("result - 0.3:", result - 0.3) # 5.551115123125783e-17

print("math.isclose(result, 0.3):", isclose(result, 0.3)) # True

**Объяснение:** Числа 0.1 и 0.2 не имеют точного представления в двоичной системе счисления. При сложении накапливается погрешность округления. Поэтому прямое сравнение == даёт False. Функция math.isclose() сравнивает числа с допустимой относительной погрешностью и является правильным инструментом для сравнения вещественных чисел.

**Правило безопасного сравнения** float**:** никогда не использовать == для сравнения вещественных чисел; использовать math.isclose(a, b) или сравнение модуля разности с допустимым эпсилон: abs(a - b) < epsilon.

3.  Строка неизменяема в том смысле, что объект, созданный в памяти, никогда не меняется. Методы вроде .upper() создают новый строковый объект с изменённым содержимым и возвращают его. Исходный объект остаётся нетронутым. Это гарантирует безопасность работы с одним объектом через несколько имён.

**Путь программы:**

1.  Исходный файл (task_5.py) - текст на языке Python в формате UTF-8.
2.  Лексический и синтаксический анализ - CPython читает текст, разбивает на токены и строит Abstract Syntax Tree (AST) - дерево, отражающее структуру программы.
3.  Компиляция в байткод - компилятор обходит AST и генерирует байткод. Байткод - последовательность инструкций виртуальной машины.
4.  Выполнение виртуальной машиной CPython - цикл eval-loop виртуальной машины последовательно читает и выполняет инструкции байткода, управляя стеком значений и пространством имён.

**Почему необходимо явное преобразование** input()**:** Функция input() всегда возвращает объект типа str. Арифметические операции (+, \*, /) не определены между строкой и числом. Попытка выполнить "8" \* 12.5 вызовет TypeError. Явные вызовы int() и float() создают новые объекты нужного типа и связывают имена с ними.

**Ответ на контрольный вопрос:** При повторном присваивании, например runs_count = 0, в Python создаётся новый объект int со значением 0, и имя runs_count перепривязывается к этому новому объекту. Старый объект не изменяется; если на него больше нет ссылок - он будет удалён сборщиком мусора. Таким образом, объекты в Python неизменяемы применительно к встроенным числовым типам - изменяется лишь то, на какой объект указывает имя.

- Выяснено принципиальное различие между именем и объектом: имя - это лишь ссылка на объект; присваивание b = a создаёт не копию, а новую ссылку на тот же объект. Оператор is проверяет идентичность объектов, а == - равенство значений.
- Исследованы базовые типы данных: int в Python имеет произвольную точность; деление / всегда возвращает float; числа с плавающей точкой имеют ограниченную точность двоичного представления, что делает прямое сравнение через == небезопасным - следует использовать math.isclose().
- Строки в Python являются неизменяемыми объектами с поддержкой Unicode; методы строк возвращают новые объекты, не модифицируя исходный.

**Три наиболее неожиданные особенности Python:**

1.  **Произвольная точность целых чисел.** В большинстве языков переполнение целого числа приводит к ошибке или некорректному результату. В Python число может быть сколь угодно большим.
2.  **Неизменяемость строк при наличии «изменяющих» методов.** Метод .upper() визуально кажется изменяющим строку, однако на самом деле создаёт новый объект.
3.  **Зависимость** is **от деталей реализации (интернирование).** Сравнение first is second для строк может давать True или False в зависимости от того, применил ли CPython интернирование. Это означает, что поведение программы может быть неочевидным без знания внутренней механики интерпретатора, и подчёркивает важность использования == для сравнения значений.
